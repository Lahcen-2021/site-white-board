A flowchart shows a process as a series of steps connected by arrows. It answers the question "what happens next?" Flowcharts are used to explain how an order is processed, how a support ticket moves through a team, how an algorithm decides, or simply how to make tea.

You do not need special software to draw one. An online whiteboard with shapes and arrows is enough, and it is often faster because you can sketch, move and rearrange freely. This guide covers the symbols, the steps and some practical tips.

## The basic flowchart symbols

Flowcharts use a small set of shapes, each with a meaning. You only need four for most diagrams:

| Shape | Meaning | Example |
|---|---|---|
| Rounded box or ellipse | Start or end | "Customer places order" |
| Rectangle | A step or action | "Check stock" |
| Diamond | A decision with yes or no | "In stock?" |
| Arrow | The direction of the flow | From one step to the next |

Some flowcharts also use a parallelogram for input and output, such as "enter password." You can draw it by hand with the pen if you need it, or simply use a rectangle and write what the input is.

On SiteWhiteboard, the shape tool (S) gives you rectangles, ellipses, triangles and diamonds. The arrow tool (L) draws connections. Arrows attach to shapes, so when you move a box the arrows follow it.

## Step 1: Decide the start and the end

Before drawing anything, write down where the process starts and where it ends. "Customer places an order" and "Order delivered" for example. This stops the flowchart from growing in every direction.

Put the start at the top of the board in an ellipse. Leave plenty of space below.

## Step 2: List the steps in order

On a sticky note or in the corner of the board, list the main steps as short phrases starting with a verb:

1. Check stock
2. Take payment
3. Pack the order
4. Send it

Writing the list first lets you think about the process without worrying about layout.

## Step 3: Draw the main path

Draw a rectangle for each step, from top to bottom, and connect them with arrows. This is the "happy path," what happens when everything goes right. Keep it in a straight vertical line if you can. It will be the spine of the diagram.

## Step 4: Add decisions

Now find the points where the process can go two ways. Each one becomes a diamond with a yes or no question: "In stock?" "Payment accepted?"

From each diamond draw two arrows. Label them "Yes" and "No" with the text tool. Usually the "Yes" arrow continues down the main path, and the "No" arrow goes to the side, to a different step such as "Tell customer item is unavailable."

## Step 5: Close every path

Follow every arrow and make sure it ends somewhere: at the end shape, or looping back to an earlier step. A path that stops in the middle of nowhere is the most common flowchart bug. For example, after "Payment failed," does the customer try again (an arrow back up to "Take payment") or does the order get cancelled (a new end shape)?

## Step 6: Tidy and check

Align the shapes, make the spacing even and check that arrows do not cross where they can avoid it. Read the flowchart out loud from start to finish, following one path at a time. If it does not make sense spoken, it will not make sense to a reader.

Then export the board as a PNG to use in a document, presentation or wiki.

## Example: a support ticket

1. Start (ellipse): "Customer sends a ticket"
2. Step (rectangle): "Read the ticket"
3. Decision (diamond): "Can first-line support answer it?" If yes, reply to the customer and go to the end. If no, continue.
4. Step: "Send it to the technical team"
5. Step: "Technical team investigates"
6. Decision: "Is it a bug?" If yes, log the bug and reply with a workaround. If no, reply with the answer.
7. End (ellipse): "Ticket closed"

Drawn on a board, this takes about ten shapes and fits on one screen.

## Tips for clear flowcharts

**One direction.** Flow from top to bottom or from left to right. Mixing directions makes a diagram hard to follow.

**Short labels.** Two to five words per shape. If you need more explanation, add a sticky note beside the shape.

**Colour for meaning.** Use a colour for steps owned by different people or teams. In the support example, first-line steps could be blue and technical steps orange. This turns a flowchart into a simple swimlane diagram.

**Sketch first, tidy later.** Start with quick hand-drawn boxes with the pen while you work out the logic. Once it is right, redraw with clean shapes.

**One process per flowchart.** If the diagram gets bigger than a screen, split part of it into its own flowchart and refer to it.

## Flowcharts in meetings and classes

Flowcharts are a great thing to draw live. In a meeting, share your screen and build the process while the group tells you the steps. Disagreements show up quickly: "No, that step happens before payment." In class, draw an algorithm as a flowchart before writing the code, or a scientific process step by step.

Because arrows stay attached, you can rearrange the diagram during the discussion without redrawing it. That is the main advantage of drawing a flowchart on an online whiteboard instead of on paper.

A flowchart does not need to be beautiful to be useful. It needs to be right. Get the steps and decisions correct first, and the neat version takes only a few extra minutes.
